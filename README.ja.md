# Crochet Weaver

**[English](README.md) | [繁體中文](README.zh-TW.md) | [简体中文](README.zh-CN.md) | [日本語](README.ja.md)**

Crochet Weaver は、Obsidian のノート内でテキストの編み図パターンをかぎ針編みチャートに変換するプラグインです。すべてローカルの Markdown コードブロック内で動作し、ネットワーク通信は一切行いません。

## 主な機能

- `crochet` コードブロックを、テーマに合わせた SVG 編み図チャートとして描画します。
- 往復編み・同心円の輪編み・連続スパイラルの 3 種類のレイアウトに対応します。
- くさり編み、細編み、中長編み、長編み、長々編み、引き抜き編み、増し目、減らし目、パフ編み、ポップコーン編み、うね編み（前後の引き上げ編み）など、一般的な編み目記号を内蔵しています。
- 段・周単位の `blo`／`flo` マーカーと、輪の作り目（わの作り目・くさり編みの輪）に対応します。
- 同心円の輪編みチャートで、次の周の最初の目に色を変更できるマーカーを表示します。
- `crochet-tool` ブロックは、目数・進捗コントロール・段ごとの目数カウンターを備えた読みやすいチェックリストとして描画されます。
- **進捗ツールまたは読み取り専用の編み図テキストを、`crochet` チャートの隣に直接埋め込めます**（`tool: on` / `text: on`）。同じパターンを 2 つのコードブロックに書く必要はありません。
- **進捗ツールを埋め込んだ場合、チャート上に現在の位置（現在の周と次の目）をリアルタイムで強調表示します**。色は設定で変更できます。
- **`color <色>` ステップで配色の変更を記録できます**。段の途中でも、段・周の先頭でも指定可能です——チャートでは色が変わった最初の目に小さな色付きの輪を表示し（針目記号自体の色は変えません）、進捗ツール／テキストパネルにも「`<色>` に変更」とそのまま表示されます。
- **パターン文字を、完全に翻訳された読みやすい表記に切り替えられます**（`readable: on`）——略記の代わりに、たとえば「6 sc」ではなく「細編み6」のように表示され、対応する 8 言語すべてで使えます。
- **ノートの幅より大きいチャートはドラッグ／スクロールできます**。無理に縮小されることはありません——マウスでドラッグするか、タッチ／トラックパッドのネイティブスクロールを使えます。表示しきれないチャートは中央から開きます。
- **設定タブから AI 向け編み図作成リファレンスをコピーできます**。4 言語に対応しており、そのまま AI とのチャットに貼り付けてパターンの変換や作成を頼めます。
- 進捗はすべてプラグインのデータファイルにローカル保存されます。
- 完全な多言語 UI：英語、繁体字中国語、簡体字中国語、日本語。

## クイックスタート

[`examples/demo.md`](examples/demo.md) では、このドキュメントで紹介している機能をすべて 1 つのノートで実際に確認できます——3 種類のチャートタイプ、すべての針目、段の修飾子、段と段をつなぐ接続線、エラー表示、進捗ツール（読みやすい表記と配色変更を含む）、パネルの配置、実際のパターン変換例です。

ノートに `crochet` コードブロックを追加します：

```crochet
---
type: round
scale: 1.25
highlight: on
---
R1: 6 sc in MR
R2: [sc, inc] x 6
R3: [2 sc, inc] x 6, sl st
```

### チャート + 進捗ツールを 1 つのソースで

`tool: on` を追加すると、インタラクティブな進捗ツール（段リスト・目数カウンター）がチャートの隣に埋め込まれます。別途 `crochet-tool` ブロックは不要です：

```crochet
---
id: coaster-small
type: round
tool: on
---
R1: 6 sc in MR
R2: [sc, inc] x 6
R3: [2 sc, inc] x 6, sl st
```

進捗管理はいらないので、チャートの隣にシンプルな略記リストだけ表示したい場合は `text: on` を使います：

```crochet
---
type: round
text: on
---
R1: 6 sc in MR
R2: [sc, inc] x 6
```

チャートなしでチェックリストだけが欲しい場合は、これまで通り独立した `crochet-tool` ブロックも使えます：

```crochet-tool
---
id: coaster-small
type: round
---
R1: 6 sc in MR
R2: [sc, inc] x 6
R3: [2 sc, inc] x 6, sl st
```

パターンのテキストを編集しても進捗を保持したい場合は、明示的に `id` を設定してください。`id` を省略すると、Crochet Weaver はコードブロックの内容からローカルハッシュを生成するため、ブロックの内容を編集すると進捗がリセットされることがあります。

## AI に編み図を書いてもらう

このプラグインを使うのに記法を覚える必要はありません。**crochet-weaver-pattern スキル**を AI アシスタントに一度渡せば、あとは本・PDF・商品説明・自分のメモなど、どんな文章の編み図でも渡して、返ってきたものをノートに貼るだけです。

1. **スキルをコピーする。** 設定 → Crochet Weaver → **編み図スキルをコピー** で、使いたい言語（English・繁體中文・简体中文・日本語）のボタンを押します。
2. **チャットを開き**（Claude でも ChatGPT でも構いません）、最初のメッセージとしてスキルを貼り付けます。単体で完結しているので、ほかに何もインストールする必要はありません。
3. **編み図を貼り付けて**、してほしいことを伝えます。例：

    > これはあみぐるみのうさぎの頭の編み図です。Crochet Weaver の `crochet` ブロック 1 つに、`type: round`、進捗ツールありで変換してください。
    >
    > R1: わの作り目に細編み 6目（6）
    > R2: 全目に増し目（12）
    > R3:（細編み 1、増し目）をくり返す（18）
    > R4〜R6: 細編み 1段（18）
    > R7:（細編み 1、減らし目）をくり返す（12）

4. **返ってきたブロックをノートに貼り**、閲覧モードかライブプレビューにします：

    ````markdown
    ```crochet
    ---
    type: round
    tool: on
    id: bunny-head
    ---
    R1: 6 sc in MR
    R2: [inc] x 6
    R3: [sc, inc] x 6
    R4: 18 sc
    R5: 18 sc
    R6: 18 sc
    R7: [sc, dec] x 6
    ```
    ````

5. **編み始める前に確認を。** チャートも段リストも AI が書いた内容から生成されます。進捗パネルの目数を、原文の `(N)` と突き合わせてください。合わない段があればチャットでそう伝えれば十分です——目数の数え方はスキルに書いてあるので、「R7 は 12目で終わるはず」と言えばたいてい直ります。

**Claude Code をお使いなら**、[`skills/crochet-weaver-pattern/`](skills/crochet-weaver-pattern/) をプロジェクトまたはホームの `.claude/skills/` に置けば、編み図を貼ったときに自動で読み込まれます。

**変換できないものがあれば**、スキルは推測せずにそう言うよう AI に指示しています——対応していない針目や、チャート上で意味を持たない指示などです。この指摘は読む価値があります。目が 1つ抜けたまま「一見それらしい」チャートのほうが、変換できないと言われるよりやっかいです。

## パターン構文

### Frontmatter

`crochet` ブロックの先頭には、シンプルな YAML 風の frontmatter を追加できます：

```yaml
---
type: flat | round | spiral
id: optional-progress-id
scale: 1.5
stroke: 2
spacing: 40
highlight: on
style: radial | japanese | continuous
tool: on | off
text: on | off
position: right | left | below
---
```

デフォルトではプラグインのグローバル設定が使われます。frontmatter に有効な値があれば、そのチャートに限りグローバル設定を上書きします。無効な値の場合はグローバル設定にフォールバックします。`tool`・`text`・`position` も同様に、それぞれのグローバルな既定値を持ち、上書きできます（詳細は「設定」を参照）。

### 段（Row）

段のラベルはどちらの書き方でも構いません：

```crochet
R1: 10 ch
Row 2: sc, hdc, dc
```

対応している段修飾子：

```crochet
R1: blo, 6 sc in MR
R2: flo, 6 sc in ch ring
```

- `blo`：その段・周全体を後ろ半目のみで編むことを示します。
- `flo`：その段・周全体を手前半目のみで編むことを示します。
- `in MR`：輪編み・スパイラルチャートに、わの作り目の中心アンカーを追加します。
- `in ch ring`：くさり編みの輪の中心アンカーを追加します。

### 編み目

対応している編み目名（アメリカ式のチャート記号に準拠）、全 46 種：

| 記号 | 分類 | 説明 |
| --- | --- | --- |
| `ch` | 基本 | くさり編み |
| `sc` | 基本 | 細編み |
| `hdc` | 基本 | 中長編み |
| `dc` | 基本 | 長編み |
| `tr` | 基本 | 長々編み |
| `dtr` | 基本 | 三巻き長編み |
| `sl st` | 基本 | 引き抜き編み |
| `MR` | 基本 | わの作り目 |
| `picot` | 基本 | ピコット（くさり 3 目の引き抜き） |
| `rsc` | 基本 | バック細編み（逆細編み） |
| `inc` | 増減目 | 増し目（細編み 2 目編み入れ） |
| `dec` | 増減目 | 減らし目（細編み 2 目一度の略記） |
| `sc2tog`、`sc3tog` | 増減目 | 細編み 2／3 目一度 |
| `hdc2tog`…`hdc5tog` | 増減目 | 中長編み 2–5 目一度 |
| `dc2tog`…`dc5tog` | 増減目 | 長編み 2–5 目一度 |
| `fpsc`、`fphdc`、`fpdc`、`fptr` | 引き上げ編み | 表引き上げ細編み／中長編み／長編み／長々編み |
| `bpsc`、`bphdc`、`bpdc`、`bptr` | 引き上げ編み | 裏引き上げ細編み／中長編み／長編み／長々編み |
| `xhdc`、`xdc`、`xtr` | 交差編み | 中長編み／長編み／長々編みの 1 目の交差 |
| `hdc2cl`、`hdc3cl`、`hdc5cl` | 玉編み／パフ | 中長編み 2／3／5 目の玉編み |
| `dc2cl`、`dc3cl`、`dc5cl` | 玉編み／パフ | 長編み 2／3／5 目の玉編み |
| `tr2cl`、`tr3cl`、`tr5cl` | 玉編み／パフ | 長々編み 2／3／5 目の玉編み |
| `bobble` | 玉編み／パフ | 汎用の玉編み／パフ編み |
| `popcorn` | ポップコーン編み | 長編み 5 目のポップコーン |
| `hdc popcorn` | ポップコーン編み | 中長編み 5 目のポップコーン |
| `tr popcorn` | ポップコーン編み | 長々編み 5 目のポップコーン |

「1 目に N 目編み入れる」増し目やシェル編みには専用名がありません——下の「グループ」の例を参照してください。

数量の接頭辞に対応しています：

```crochet
R1: 10 ch, 6 sc
```

繰り返しは角括弧を使います。`x 6` でも `rep 6` でも同じです：

```crochet
R2: [sc, inc] x 6
R2: [sc, inc] rep 6
```

回数を書かない `rep` は「下の段の目がなくなるまで繰り返す」という意味なので、自分で数える必要はありません：

```crochet
R1: mr, ch, sc6, slst
R2: ch, [2 sc, inc] rep, slst
```

`[2 sc, inc]` は1回で3目に編み入れ、R1 は6目なので2回になります。割り切れないときは、勝手に決めずにエラーとして知らせます。

目数は名前の前でも後ろでも構いません（`6 sc`、`sc6`、`sc 6` は同じ）。引き抜き編みは `sl st`、`slst`、`sl-st`、`sl_st` のどれでも書けます。

段の最初の立ち上がりの鎖と最後の引き抜き編みは、その段の継ぎ目に描かれますが、どちらも段の目数には入りません。次の段はその間の目に編み入れます。

グループは丸括弧を使い、1 つの目の位置から扇状に展開されます。「1 目に N 目編み入れる」増し目やシェル編みもこの書き方で表します（`2dc-in-1` のような専用名はありません。`(dc, dc)` や `(5 dc)` がそのままそのチャート記号になります）：

```crochet
R3: (dc, ch, dc), sc, (5 dc)
```

### レースとモチーフ

レースの編み図は前段を数えながら進むのではなく、1目ずつ「どこに編み入れるか」を書きます。Crochet Weaver はその書き方をそのまま読みます。

```crochet
---
type: round
style: japanese
---
R1: MR, ch 3 (counts as dc), 23 dc in MR,
    sl st to top of beginning ch-3. (24 dc)

R2: ch 1 (does not count as a st),
    sc in same st, ch 1,
    [sc in next dc, ch 1] x23,
    sl st to first sc.
    (24 sc + 24 ch-1 sp = 48 sts)

R3: sl st into next ch-1 sp,
    ch 3, 2 dc in same ch-1 sp,
    sc in next ch-1 sp,
    [3 dc in next ch-1 sp,
     sc in next ch-1 sp] x11,
    sl st to top of beginning ch-3.
    (12 reps, 4 sts per rep)

R4: turn,
    [V2 in next sc, ch 1,
     sc in center dc of next 3-dc shell,
     picot, ch 1] x12,
    sl st to join.
```

| 書き方 | 意味 |
| --- | --- |
| `in next dc`／`in next ch-2 sp`／`in next picot` | その種類の次の場所。途中にあるものは自動的に通り越します |
| `in same st`／`in same ch-1 sp` | 直前のステップと同じ場所。そこに編んだ目は同じモチーフになります |
| `in center dc of next 7-dc shell` | 次の7長編みシェルの中央の目 |
| `5 dc in next ch-2 sp` | 1か所に編み入れる5目のシェル。扇として描かれます |
| `V2`／`V3` | `(dc, ch 2, dc)`／`(dc, ch 3, dc)` を同じ場所に。内側の鎖はそれ自体が空間になります |
| `ch 3 (counts as dc)` | 立ち上がりの鎖が1目の代わりになります |
| `sl st into next ch-1 sp` | 引き抜きでその空間まで移動。まだ何も編み入れません |
| `turn` | 段の先頭に書く：この段は逆向きに編みます |
| `R15-R18: repeat R11-R14.` | チャートを描く前に実際の段へ展開されます |

frontmatter に `lace: on` を加えると、編み物本がレースを印刷するように描かれます。段を囲む線を引かず、段数も書かず、透かしに映えるよう記号を大きめに描きます。変わるのはパターンの周りに何を描くかだけで、パターンそのものは変わりません。

`wholeRounds: 4` を併せて指定すると、最初の4段は丸ごと描き、その先から扇形になります。中心の数段は模様がまだ決まっていく途中なので、本も丸ごと描きます。`sector: 90`（または 90 度を意味する `sector: on`）を加えると、**円全体ではなく扇形の一区画だけ**を描きます。同じモチーフが12個並ぶ段は、その一切れで言うべきことをすべて言っており、本もそう印刷します。チャート全体は変わらず計算され、描かれるのは段の変わり目から始まる一区画だけです。境界にかかったモチーフは半分に切らず、まるごと残します。

2つの針目のあいだの鎖のひと続きは、次の段が編み入れられる1つの空間になり、その鎖は1目ずつ描かれて数えられます。注記のない立ち上がりの鎖は、その段が鎖の頭にとじていれば1目として数えます──原文のままで、注記を足す必要はありません。

レースは `japanese` と `continuous` の輪編みスタイルで描かれます。どちらも「どこに編み入れたか」から目の位置を決めます。`radial` は従来どおり、段を均等に配置します。

### 配色の変更

`color <色>` ステップ（CSS の色名か `#hex` コード）は、糸を切り替える位置を示します。段の途中でも、段・周の先頭でも書けます：

```crochet
R6: 8 sc, color white, 8 sc, color black, 8 sc
```

このステップ以降のすべての針目——この段の残りと、それ以降のすべての段——にこの色が適用され、次の `color` ステップで変更されるまで有効です。「色指定なしに戻す」トークンはありません。針目の記号自体は常に編み図本来のテーマカラーのままです。代わりに、新しい色に変わった最初の針目に小さな中抜きの輪が表示され、進捗ツール／パターン文字パネルにも「`<色>` に変更」とそのまま表示されます。

## チャートの種類

### 往復編み（Flat）

`type: flat` は各段を左右交互に往復するレイアウトで描画します。

```crochet
---
type: flat
---
R1: 10 ch
R2: 10 sc
R3: 10 dc
```

### 同心円の輪編み（Round）

`type: round` は各段を同心円状の周として描画します。段の末尾の `sl st` は引き抜きとして扱われ、その周の目数間隔の計算からは除外されます。

```crochet
---
type: round
---
R1: 6 sc in MR
R2: [sc, inc] x 6, sl st
```

`style: japanese` を指定すると、輪編みチャートが日本の編み物本のスタイルに切り替わります：連続した1本のらせん線が各段を巡り（輪編みは実際に1本のらせんで、独立した閉じた円の重なりではありません）、各段の立ち上がり位置で外側の段へステップし、その位置に段数を赤で表示します。

増し目・減らし目は編み物本と同じ描き方です。どちらも**その段自身の記号**として、普通の目と同じ帯の上に並びます。`inc` は **V**：頂点が段の内側の線に乗って編み入れ先の目と揃い、2本の腕が段の外側の線まで開いて、作られた各目（次段の編み入れ先）を表します。`dec`（および `scNtog`）は **∧**：両足が編みくるんだ各目に、頂点がその上に立ちます。段と段のすき間に浮くものはなく、固定図形でもありません。各記号はその段の帯幅に合わせた大きさで、対応する目のほうへ傾きます。対応する目に届くだけは開きますが、V に見えなくなるほどは開きません。外側の段で大きく離れた2目を減らす場合も、両方へ向かって開くだけで2本の長い線に伸びることはありません。

内部では、すべての針目が前段の編み入れ先の目から配置され、それを記録しています。増し目の2目は同じ元の目を共有し、減らし目の1目は2つの元の目を持ちます。針目は編む順序を入れ替えられることも、重なることもなく、増減で生じた余白は近くの針目で分け合います。

`style: continuous` は同じレイアウトのまま、対応関係を記号で表す代わりに線で描き出します。すべての針目が自分の記号を保ち（**増し目が作る2目も両方**）、そこから前段の編み入れ先の目へ線が引かれます。パターンの確認や、本の記号にまだ慣れていないときの読み取りに向いています。

どちらのスタイルでも、グループにまとめたり詰めたりはしません。各針目は編み入れ先の目にそのまま従います。`[2 sc, inc] x 6` のように繰り返しで書かれた段が6つの扇形として読めるのは、6つの増し目がそれぞれ編み入れ先の目の真上に来るからであって、チャートが寄せて詰めているからではありません。繰り返しも増減も持たない段（かごの側面の `R9: 40 sc` など）は下の段をそのまま写すので、普通の段が続くときは、下の増減が残した位置の上へまっすぐな放射状の列として積み上がります。

既定の `style: radial` は従来の均等配置と従来の `inc`／`dec` 記号のままです。グローバル設定「輪編みチャートのスタイル」で全チャートの既定を変更できます。

```crochet
---
type: round
style: japanese
---
R1: 6 sc in MR
R2: [inc] x 6
R3: [sc, inc] x 6
R4: [2 sc, inc] x 6
```

### 連続スパイラル（Spiral）

`type: spiral` はすべての段を 1 本の連続したスパイラルに沿って描画します。

```crochet
---
type: spiral
---
R1: 6 sc in MR
R2: [sc, inc] x 6
R3: [2 sc, inc] x 6
```

## 空白の下描きグリッド

`crochet-grid` は、手描きで新しいデザインを下描きするための空白グリッドを描画します。編み目も進捗管理もなく、ガイドとなる図形だけです。

```crochet-grid
shape: polar
rounds: 6
columns: 12
```

- `shape: polar`（既定）は `rounds` 個の同心円と、`columns` 本の等間隔な放射線を描画します。
- `shape: rect` は代わりに `rows` × `columns` の長方形メッシュを描画します。

  ```crochet-grid
  shape: rect
  rows: 8
  columns: 8
  ```

- `scale`、`stroke`、`spacing` は `crochet` チャートと同じように働きます。`spacing` は `polar` では輪の間隔、`rect` ではマスのサイズを指定します。
- 「**空白のかぎ針編みグリッドを挿入**」コマンドを実行すると、現在のグリッド既定値で埋められた雛形ブロックが挿入されます。

## チャートの背景参考グリッド

上の独立した空白グリッドとは異なり、実際の `crochet` ブロックに `grid: on` を付けると、実際のチャートの背後に、その実際のジオメトリに合わせた薄い参考グリッドが描画されます。「今どの周を編んでいるか」がひと目で分かるので、埋め込みの進捗ツールと組み合わせると特に便利です。

```crochet
---
type: round
grid: on
---
R1: 6 sc in MR
R2: [inc] x 6
R3: [sc, inc] x 6
R4: [2 sc, inc] x 6, sl st
```

- `type: round`／`type: spiral`：各周に、その周の実際の半径に合わせた参考円が 1 つ描かれます（スパイラルには本来の意味での「周」がないため、「N 周目」の参考円は N 段目の終わりにスパイラルが到達している半径で近似します）。参考の放射線（スポーク）は、既定では最も外側の周の目数に合わせた本数で、等角度に配置されます。
- `type: flat`：チャートの実際の段の高さと目の幅に合わせた行／列のメッシュを描画します。これはあくまで参考用の座標系であり、往復編みは段ごとに方向が反転するため、1 段目以降のすべての目が交点に正確に一致するとは限りません。
- 既定では、グリッドはパターン自体の実際の範囲に自動的に合わせられるため、追加の設定は不要です。`rounds:`（輪編み／スパイラル）または `rows:`（往復編み）、および／または `columns:` を追加すると、実際のパターンを超えてグリッドを拡張できます（例えば、あと何周くらい必要になりそうかを事前に確認したい場合など）。これらの設定はグリッドを拡張することしかできず、実際の範囲より小さく縮めることはできません。
- 「**背景の参考グリッドを表示**」設定を使うと、すべてのチャートで既定でこのグリッドを表示できます。

## 進捗ツールや編み図テキストの埋め込み

`crochet` ブロックの `tool`／`text` frontmatter キー（またはそれに対応するグローバル設定）を使うと、チャート自身に進捗パネルを持たせることができ、パターンを一度書くだけで済みます：

- `tool: on` — 完全なインタラクティブ進捗ツール（段リスト、進捗バー、`+1`／`−1`／リセット付きの段ごとの目数カウンター、前の周／現在の周を完了／リセットのコントロール）をチャートの隣に埋め込みます。
- `text: on` — 読み取り専用の略記リスト（ラベル、正規化された編み目、目数）を埋め込みます。進捗管理やボタンはありません。図の隣に略記だけ表示したい場合に便利です。
- 両方が有効な場合は `tool` が優先されます（`text` が表示する内容はすべて含まれているためです）。
- `position: right | left | below` で、パネルをチャートに対してどこに配置するかを指定します。`right`（既定）と `left` は横並びで、幅が狭い場合は自動的に縦積みレイアウトに折り返されます。`below` は常に縦積みです。

## 進捗ツール

埋め込み（`tool: on`）でも独立した `crochet-tool` ブロックでも、進捗ツールは 2 つの粒度で進捗を管理します：

- **段・周の進捗** — 段をクリックするとその段にジャンプします。前の周／現在の周を完了／リセットのボタンも使えます。セグメント表示のバーで、完了した段数がひと目で分かります。
- **目数カウンター** — 現在の段について、実際に編み目を 1 目編むたびに `+1` をタップします。その段の総目数に達すると自動的にその段が完了扱いになり、カウンターは 0 にリセットされます。そのため、段の境目を気にせず `+1` をタップし続けられます。`−1` は数え間違いの修正に、リセットボタンは段の進捗には影響を与えずに現在の段の目数だけをクリアするのに使えます。前の周に戻る・現在の周を完了する・リセットする・別の段をクリックする、といった操作を行うと、新しい現在の段の目数カウンターは 0 にリセットされます。

進捗ツールがチャートと同じブロックに埋め込まれている場合（`tool: on`）、チャートは現在の位置をリアルタイムで強調表示します。現在の段は薄い色で、次に編むべき正確な目にはより強い強調表示が付き、どちらも「**チャートの現在位置マーカー色**」の設定で指定した色が使われます。独立した `crochet-tool` ブロックや `text: on` パネルには対応するチャートがないため、この強調表示は行われません。

## 設定

プラグインの設定タブから、以下のグローバルな既定値を設定できます：

- **言語**：Obsidian に合わせるか、8 言語（英語・繁体字中国語・簡体字中国語・日本語・韓国語・ドイツ語・フランス語・スペイン語）から選択します。針目名とすべてのメッセージは 8 言語すべてに翻訳されています。AI 向け作成リファレンスは最初の 4 言語です。
- **チャートの拡大率**：チャートの表示倍率です。
- **記号の線幅**：編み目記号の線幅です。
- **輪の間隔**：輪編み／スパイラルの各輪の間隔です。
- **増し目と減らし目を強調**：`inc` と `dec` をアクセント色で表示します。
- **増し目・減らし目の色**：上の強調を有効にしたとき、増し目と減らし目の記号を描く色です。
- **チャートの現在位置マーカー色**：チャートに進捗ツールが埋め込まれているとき、現在の周・目を強調する色です。
- **進捗ツールを既定で表示**：すべての `crochet` チャートに進捗ツールを既定で埋め込みます。`tool: on/off` で個別に上書きできます。
- **編み図テキストを既定で表示**：すべての `crochet` チャートに読み取り専用の編み図テキストを既定で埋め込みます。`text: on/off` で個別に上書きできます。
- **パネルの位置**：埋め込まれたツールまたはテキストパネルの既定位置（右／左／下）です。`position:` で個別に上書きできます。
- **背景の参考グリッドを表示**：すべての `crochet` チャートに既定で周／段の参考グリッドを表示します。`grid: on/off` で個別に上書きできます。
- **輪編みチャートのスタイル**：`standard`（針目を均等配置）、`japanese`（連続らせんの区切り線、前段の目から配置、本と同じ V／∧ の増減記号、段数表示）、`continuous`（同じレイアウトで全目を描き、前段へ線で接続）。
- **グリッドの既定の形状**：新しい `crochet-grid` ブロックの既定の形状です（`polar` または `rect`）。
- **グリッドの既定の周数**：放射状グリッドの既定の周数です。
- **グリッドの既定の列数**：グリッドブロックの既定の列数／放射線の本数です。
- **グリッドの既定の行数**：長方形グリッドの既定の行数です。

「個別に上書きできます」と記載のある設定は、対応する frontmatter キー（`scale`、`stroke`、`spacing`、`highlight`、`style`、`tool`、`text`、`position`、`grid`）で 1 枚のチャートごとに上書きできます。`chartMarkerColor` はグローバル設定のみです。`crochet-grid` ブロックは独自の設定キー（`shape`、`rounds`、`columns`、`rows`、および `scale`／`stroke`／`spacing`）を使います。実際のチャート上の `grid` 参考グリッドが使う `rounds`／`rows`／`columns` は、そのチャート自体の frontmatter に追加で指定するもので、実際の範囲を拡張することしかできません。

## 安全上の制限

Crochet Weaver は、レイアウトを展開する前に解析済みのチャートを検証します。段数・目数・繰り返し回数・入れ子の深さ・総描画目数が極端に多い場合は、Obsidian のプレビューがフリーズするのを防ぐため、インライン表示のエラーとして処理を拒否します。

現在の制限：

- 最大段数：200 段
- 目数の最大接頭辞：1000
- 最大繰り返し回数：500 回
- 最大総描画目数：5000 目
- 最大入れ子の深さ：8 階層
- グリッドの最大周数：40 周（`crochet-grid` ブロックと `crochet` チャートの `grid: on` の `rounds:` 上書きの両方に適用）
- グリッドの最大列数：72 列（適用範囲は上と同じ）
- グリッドの最大行数：40 行（適用範囲は上と同じ）

## プライバシー

Crochet Weaver は Obsidian 内で完全にローカルに動作します。

- テレメトリなし。
- ネットワーク通信なし。
- Vault 全体のスキャンなし。
- パターンのテキストは、描画対象のコードブロックからのみ解析されます。
- 進捗（段の進捗と目数）は、プラグインの `data.json` ファイルにローカル保存されます。

## 開発

依存関係のインストール：

```bash
npm install
```

テストの実行：

```bash
npm test
```

プラグインのビルド：

```bash
npm run build
```

Lint の実行：

```bash
npm run lint
```

パーサーは `src/pattern/grammar.peggy` から `src/pattern/parser.ts` に生成されます。生成されたファイルを手動で編集しないでください。

### AI を使ったパターン作成

アシスタントに必要な知識は [`skills/crochet-weaver-pattern/`](skills/crochet-weaver-pattern/) にあります——`SKILL.md` と `.zh-TW`・`.zh-CN`・`.ja` 版です。使い方は「AI に編み図を書いてもらう」を参照してください。SKILL ファイルを編集したら `npm run generate-skill` を実行し、プラグインに埋め込まれるコピー（`src/skill-content.ts`）を更新してください。ビルド・テスト・lint はいずれも先にこれを実行し、両者をバイト単位で比較するテストもあります。

## 手動インストール

プラグインをビルドし、以下のファイルを Vault のプラグインフォルダーにコピーします：

```text
<Vault>/.obsidian/plugins/crochet-weaver/
  manifest.json
  main.js
  styles.css
```

Obsidian を再読み込みし、**設定 → コミュニティプラグイン**で **Crochet Weaver** を有効化してください。

## リリース手順

1. `manifest.json` と `package.json` を同じ SemVer バージョンに更新します。
2. `versions.json` を更新し、プラグインバージョンが必要な最小 Obsidian バージョンに対応するようにします。
3. `npm test`、`npm run build`、`npm run lint` を実行します。
4. manifest のバージョンと完全に一致する（先頭に `v` を付けない）Git タグを作成します。
5. `manifest.json`、`main.js`、`styles.css` をリリースアセットとして添付した GitHub Release を公開します。
